# Finny · учебные события и задания, 22 ноября 2026

## Какие изменения вошли

- Симулятор начинает нумерацию попыток заново для каждого задания в каждой сессии, как регистратор мобильного приложения. В выгрузке `prior_sessions` хранит число предыдущих сессий ребёнка с этим заданием. Повтор после ошибки в той же сессии не увеличивает этот показатель.
- В уроке с роликами за 75 монет экран сдачи показывает стоимость и уплаченную сумму. Платёж ровно на 75 по-прежнему сразу завершает урок. За такую покупку наблюдение по сдаче не записывается.
- Три утверждения получили новые формулировки и ключи. В девяти карточках пять верных утверждений и четыре неверных. Теперь клиент берёт текст и правильный ответ карточки из того же JSON, что сервер и симулятор.
- В каждом из трёх уроков о платежах появились два числовых задания. PAY-3 проверяет подсчёт и размен монет, PAY-1 — сумму цен и стоимость нескольких билетов, PAY-2 — сдачу за билет и остаток после покупки. Ошибка даёт подсказку и возможность ответить ещё раз.
- Учебный каталог v2 содержит 41 актуальное задание. Версию 2 получили `budget-4.swipe.2`, `savings-4.swipe.2`, `payments-3.swipe.2` и `payments-2.change`. Сервер также загружает четыре исходные версии, чтобы принимать очередь более ранних клиентов. Новые задания начинаются с версии 1.
- Число актуальных заданий по выбранной цепочке: PAY-3 — 9, PAY-1 — 4, PAY-2 — 5. Это число отдельных идентификаторов. Несколько наблюдений сортировки относятся к одной механике.

## Приёмка на телефоне

1. На компьютере из папки finny выполни `docker compose up -d`, затем `docker compose exec api python -m app.seed_content`. Запусти `npx expo start --dev-client` и открой проект в установленном клиенте разработки Finny. Телефон и компьютер должны иметь доступ друг к другу. Для проверки нужен тестовый профиль с доступом к главе «Платежи и покупки».
2. Открой второй урок главы, «Заплати за покупку». На первом числовом шаге про размен четырёх монет по 2 введи 7. После подсказки нажми «Попробовать», очисти поле клавишей C, введи 8. Должно появиться «Верно!».
3. Продолжи урок. За билет ценой 24 при оплате 40 введи 16. За ролики ценой 75 положи две монеты по 50. До ввода сдачи экран должен показывать 75 и 100. Собери 25 (10 + 10 + 5), заверши урок.
4. Снова открой этот урок, на вопрос про размен сразу ответь 8. Выйди из урока, чтобы отправить очередь. В другом прохождении можно заплатить за ролики ровно 75 и проверить ветку без сдачи.
5. В терминале запусти `docker compose exec db psql -U finny -d finny`. Выполни запрос ниже. Если есть несколько тестовых детей, используй идентификатор своего профиля в условии WHERE. Для одного профиля смотри строки своего последнего прогона. Ожидание: в первой сессии (7, попытка 1, ошибка), (8, попытка 2, верно), в новой сессии (8, попытка 1, верно).
6. В карточках третьего урока выбери «Неверно» для утверждения, что со сдачей за билет стоимостью 30 при оплате 50 должны вернуть 10. Проверь, что приложение объясняет расчёт 50 − 30 = 20.

```sql
SELECT child_id, session_id, answer, attempt_no, is_correct, task_version
FROM learning_events
WHERE task_id = 'payments-2.practice.pairs'
ORDER BY child_id, occurred_at, device_seq;
```

Автоматические проверки включают повторяемость симуляции, сверку событий с серверным грейдером и обработку двух версий карточки. Контрольный сценарий симулятора закреплён в `ml/tests/test_simulator.py`. В отдельной проверке мобильный регистратор прошёл этот сценарий при имитации фокуса экрана и очереди. Удобство ввода, вёрстку и передачу события с физического устройства проверяют по шагам выше.
