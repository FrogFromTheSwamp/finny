## 1. О проекте
 
Мобильное приложение по финансовой грамотности для детей 7–11 лет (игра с питомцем Финни) и родительский режим. ВКР: «Разработка адаптивной мобильной обучающей системы для формирования финансовой грамотности детей с применением методов машинного обучения».
 
Стек: React Native + Expo + TypeScript (`src/`); FastAPI + SQLAlchemy 2 + Alembic + PostgreSQL 17 в Docker Compose (`server/`); Python-аналитика и симулятор (`ml/`, Jupyter). Язык общения, комментариев и текстов для диплома — русский.
 
Принципы: offline-first; нет реальных денег, рекламы, лутбоксов; настоящее имя ребёнка на сервер не передаётся (152-ФЗ); правильность ответов и начисления считает сервер; журналы только дописываются.

## 7. Правила данных и ML (самое важное)
 
1. **Данные разработки за 18–20.11.2026 для обучения и оценки не использовать** (были баги: фантомные abandoned-сессии, ложные ошибки из-за двойного тапа). Модели — только на синтетике и данных пилота.
2. **Симулятор НЕ должен генерировать ответы по модели BKT.** Синтетические дети строятся агентной симуляцией (персоны в `personas.py`, поведение в `learner.py`/`answers.py`). Иначе оценка BKT круговая. Если в `learner.py`/`answers.py` увидишь BKT-подобную логику освоения (p_learn, slip, guess) — не правь молча, а сообщи и опиши, насколько это влияет на выводы.
3. **`mastery_truth.csv` (поля `true_p`, `true_mastery`) — скрытая «истина» симулятора.** Никогда не использовать как признак или вход модели и не открывать в коде обучения (`compare_models.py` его не читает, так и оставить). Читать можно только в отдельном модуле оценки, после обучения, чтобы сравнить оценку P(L) с истинным освоением (корреляция, калибровка, траектории). У виртуального ребёнка нет «истинного p_learn»: **не писать «восстановление истинных параметров BKT»**, писать «согласие оценки освоения с истинным освоением симулятора».
4. **Разбиение train/test — по детям**, не по событиям; внутри ребёнка порядок по времени; никаких «будущих» данных в признаках.
5. **Воспроизводимость:** явные seed; seed и версия набора данных в выходе. Какой набор актуален (`sim_v1` или `sim_v3`), смотри в их `meta.json`; наборы не удалять и не перегенерировать без запроса, результаты всегда подписывай версией набора.
6. **Цель:** правильность первой попытки следующего задания. Метрики: AUC и RMSE. Сравнение: BKT (своя), pyBKT (сверка реализации), базовые модели (глобальная доля, доля по навыку), PFA. Всегда указывай число детей и событий.
7. **Подозрительные цифры** (AUC ≥ 0.95, либо ровно 0.5 у обучаемой модели) — сначала ищи утечку/баг, потом сообщай. Исключение: константная базовая модель «доля верных по навыку» внутри одного навыка даёт AUC = 0.5 по построению, это не ошибка.
7a. **Параметры BKT на границе допустимого интервала** (p_guess/p_slip = 0.499, p_learn = 0.999) считай неидентифицированными: не выдавай их за оценки и не интерпретируй содержательно. В таблицах и текстах помечай такие значения явно. Границы подбирать на валидационной выборке (часть обучающих детей), не на тесте.
7b. **BKT не знает сложности конкретного задания** (один навык = одна пара guess/slip). Если внутри навыка задания разной трудности (пример: BUD-4, `budget-1.shop.basket` ≈48% верных против `budget-3.shop.reserve` ≈86%), рост доли верных может ошибочно читаться как обучение. Учитывай при интерпретации и описывай как ограничение.
7c. **Доверительные интервалы считать с пересэмплированием детей целиком** (кластерный бутстреп), потому что ответы одного ребёнка зависимы.
8. **Синтетика не доказывает качество обучения реальных детей.** Пиши честно: проверяется работоспособность пайплайна и восстановление параметров.
9. Выводы для диплома не писать, если не просили; давай цифры, описание метода, графики. Тексты на русском, научный стиль, без выдуманных источников.
