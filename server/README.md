# Сервер Finny

FastAPI + PostgreSQL, запускаются через Docker Compose.

## Запуск

Из папки `finny` (там, где лежит `docker-compose.yml`):

```
docker compose up --build
```

Первый запуск занимает несколько минут: скачиваются образы и ставятся библиотеки.

Проверка:
- http://localhost:8000/health — сервер отвечает
- http://localhost:8000/health/db — сервер видит базу
- http://localhost:8000/docs — автоматическая документация API (Swagger)

## Остановка

- `Ctrl+C` в окне, где запущен сервер, или `docker compose down`
- `docker compose down -v` — остановить **и удалить данные базы** (начать с чистого листа)

## Что где лежит

| Файл | Зачем |
|---|---|
| `docker-compose.yml` | какие контейнеры запускать и как они связаны |
| `server/Dockerfile` | как собрать образ сервера |
| `server/requirements.txt` | Python-библиотеки сервера |
| `server/app/main.py` | эндпоинты API |
| `server/app/db.py` | подключение к PostgreSQL |
| `server/app/models/` | описание таблиц базы (SQLAlchemy) |
| `server/migrations/` | миграции Alembic: история изменений структуры базы |

Код в `server/` подключён в контейнер напрямую: после сохранения файла сервер перезапускается сам, пересобирать ничего не надо. Пересобирать (`--build`) нужно только после изменения `requirements.txt` или `Dockerfile`.

## Миграции (изменение структуры базы)

Сервер должен быть запущен. Во втором окне PowerShell, из папки `finny`:

1. Поменяла модели в `server/app/models/` → создать миграцию:
   ```
   docker compose exec api alembic revision --autogenerate -m "что изменилось"
   ```
   В `server/migrations/versions/` появится новый файл — его стоит открыть и проверить глазами.
2. Применить миграции к базе:
   ```
   docker compose exec api alembic upgrade head
   ```
3. Посмотреть таблицы:
   ```
   docker compose exec db psql -U finny -c "\dt"
   ```

Откатить последнюю миграцию: `docker compose exec api alembic downgrade -1`.

## Тесты

Сервер должен быть запущен. Из папки `finny`:

```
docker compose exec api pytest -v
```

Тесты используют отдельную базу `finny_test` (создаётся автоматически) и не трогают данные разработки.
Перед запуском база пересоздаётся миграциями, после каждого теста таблицы очищаются.

## Параметры BKT и пересчёт освоения (шаг 4.5b)

Из корня Finny в терминале PowerShell при запущенных контейнерах:

```powershell
cmd /c "docker compose exec -T api python -m app.import_bkt_params < ml\results\knowledge_models_v4_plearn.json"
docker compose exec -T api python -m app.rebuild_mastery
```

Первая команда читает итоговые параметры 11 навыков из `test.by_skill`, обученные на 240 виртуальных детях. Версия — `bkt-sim-v3-v2`. Повторная загрузка того же набора сохраняет время создания строк. Ошибка параметров или конфликт версии отменяет весь импорт. В `bkt_params.metrics` сохраняются источник, выборка, хеши, критерий выбора, потолок, AUC/RMSE и список граничных параметров. У обученной модели `reliable` означает отсутствие параметров на границе.

Вторая команда перечитывает журнал в хронологическом порядке отдельно для каждого ребёнка. В `mastery.attempts` попадает число учтённых первых ответов; ответы одного шага дают один переход BKT. Если в сессии сохранилось несколько первых ответов на одно задание, учитывается самый ранний по `received_at`, при совпадении — по `device_seq`, затем UUID. Строки без сессии или оценки пропускаются. Если активных параметров нет, используется `bkt-default-v1` (0,2 / 0,1 / 0,25 / 0,15 в порядке init / learn / guess / slip) с `reliable=false`. После импорта обученной версии повторите команду пересчёта. Повторный пересчёт при том же журнале и модели сохраняет `updated_at`.
