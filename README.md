# Finny

**Finny — мобильное приложение, в котором дети учатся финансовой грамотности через игру с питомцем.** Ухаживай за Финни, проходи уроки, планируй расходы и копи игровые монеты на цели.

> Доступна предварительная версия **v1.0.0**. APK предназначен для Android.

## Что есть в приложении

- Знакомство с питомцем, кормление и гардероб.
- Игровой счёт, копилка, цели накопления и история операций.
- 11 интерактивных уроков в трёх главах: «Бюджет», «Сбережения», «Платежи и покупки».
- Ежедневные награды, опыт и учебный прогресс. После главы «Бюджет» питомец взрослеет.
- Взрослый раздел с локальным PIN и просмотром прогресса ребёнка.

Все монеты и покупки игровые: реальных платежей и подключения к банковским счетам нет. Прогресс сохраняется на устройстве через AsyncStorage; синхронизации между устройствами нет. Удаление приложения или очистка его данных может привести к потере сохранений.

## Как установить на Android

1. Нажми **«Скачать APK для Android»** выше.
2. Открой скачанный файл `finny.apk` на телефоне.
3. Если Android запросит разрешение, разреши установку из используемого браузера или файлового менеджера.
4. Нажми **«Установить»** и открой Finny.

Для готового APK не нужны Node.js, Expo Go или подключение к компьютеру. Для обновления скачай новый APK и установи его поверх предыдущего. Чтобы Android принял обновление, сохраняй идентификатор приложения и ключ подписи, а номер сборки увеличивай.

## Запуск проекта для разработки

Стек: **Expo SDK 57 · React Native · Expo Router · TypeScript · Zustand**.

Понадобятся Git, Node.js и npm. Для тестов используй Node.js 24 LTS: тесты импортируют TypeScript напрямую.

```bash
git clone https://github.com/FrogFromTheSwamp/finny.git
cd finny
npm ci
npm start
```

`npm start` запускает Metro — сервер разработки Expo. Для локальной Android-сборки нужны Android SDK и настроенный эмулятор либо подключённый телефон. Для iOS нужны macOS и Xcode.

| Команда | Назначение |
| --- | --- |
| `npm start` | Запуск сервера разработки Expo |
| `npm run android` | Создание и запуск локальной Android-сборки |
| `npm run ios` | Создание и запуск локальной iOS-сборки на macOS |
| `npm run web` | Запуск веб-версии для разработки |
| `npm run typecheck` | Проверка TypeScript |
| `npm test` | Проверка игровых правил |

Мобильные экраны проверяй на устройстве: веб-режим не заменяет проверку жестов и клавиатуры. Совместимость с Expo Go зависит от поддержки нативных модулей проекта; при ошибке отсутствующего модуля используй локальную сборку через `npm run android`.

## Как получить APK

В `eas.json` уже есть профиль `preview` с внутренним распространением. Для Android он создаёт устанавливаемый APK.

1. Установи зависимости проекта: `npm ci`.
2. Войди в Expo-аккаунт с доступом к EAS-проекту, указанному в `app.json`:

   ```bash
   npx eas-cli@latest login
   ```

3. Запусти облачную сборку:

   ```bash
   npx eas-cli@latest build --platform android --profile preview
   ```

4. Следуй подсказкам EAS по подписи приложения. Для обновлений используй тот же ключ подписи.
5. После завершения открой ссылку на сборку, скачай APK и переименуй его в **`finny.apk`**.

Профиль `preview` создаёт самостоятельное приложение, которому не нужен Metro. Профиль `production` предназначен для выпуска в магазин и обычно создаёт AAB; для кнопки в README используй APK из `preview`.

Перед новым выпуском обнови `expo.version` в `app.json` и увеличь Android version code в EAS. Здесь используется удалённый источник версий (`appVersionSource: remote`); управлять номером можно командой `npx eas-cli@latest build:version:set`.

[Инструкция Expo по сборке APK](https://docs.expo.dev/build-reference/apk/).

## Как выложить APK на GitHub

Если APK уже готов, начни с этого раздела. Файл прикрепляется к релизу — добавлять его в исходники через Git не требуется.

1. Открой [релизы Finny](https://github.com/FrogFromTheSwamp/finny/releases).
2. Нажми **Draft a new release** или **Create a new release**.
3. В поле тега укажи новую версию, например `v1.0.0`, и выбери создание нового тега. В качестве целевой ветки выбери ветку с кодом этой сборки.
4. Укажи название, например **Finny 1.0.0**, и кратко опиши изменения.
5. В область вложений перетащи файл **`finny.apk`**. Дождись окончания загрузки.
6. Для версии, на которую должна вести кнопка, не включай **pre-release** и отметь **Set as the latest release**, если этот пункт доступен.
7. Нажми **Publish release** и проверь скачивание по кнопке в начале README.

Кнопка в начале README сейчас ведёт прямо на APK предварительной версии `v1.0.0`:

```text
https://github.com/FrogFromTheSwamp/finny/releases/download/v1.0.0/finny.apk
```

После публикации обычного релиза можно заменить адрес кнопки на постоянную ссылку на последний стабильный выпуск:

```text
https://github.com/FrogFromTheSwamp/finny/releases/latest/download/finny.apk
```

Для следующей версии создай новый релиз, например `v1.0.1`, и снова прикрепи APK с именем **`finny.apk`**. При прямой ссылке обнови тег версии в адресе кнопки. Ссылка через `latest` не требует изменения для следующих стабильных выпусков, но не выбирает предварительные релизы. В публичном репозитории APK доступен всем; в приватном — пользователям с доступом к репозиторию.

[Инструкция GitHub по публикации релизов](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).

## Где что находится

| Путь | Содержимое |
| --- | --- |
| `src/app/` | Экраны и маршруты Expo Router |
| `src/app/lesson/[id].tsx` | Интерактивные задания уроков |
| `src/features/learning/` | Главы, уроки и последовательности заданий |

| `src/features/budget/BudgetControls.tsx` | Общие элементы управления бюджетом |
| `src/game/store/gameStore.ts` | Игровое состояние и сохранения |
| `src/store/profileStore.ts` | Профиль и настройки |
| `src/assets/library/`, `src/assets/branding/` | Графика приложения |
| `tests/` | Тесты игровых правил |
| `app.json`, `eas.json` | Настройки приложения и сборок |

Алиас `@/` указывает на `src/`. При изменении контента сохраняй стабильные ID: на них могут ссылаться сохранения пользователей. Правила работы с проектом собраны в [AGENTS.md](AGENTS.md), дополнительные сведения — в [documents/README.md](documents/README.md).
